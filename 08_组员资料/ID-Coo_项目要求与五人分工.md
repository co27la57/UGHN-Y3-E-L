## 0. 一页速览

- **任务**：为英格兰北部奶农（起步品种 Holstein Friesian）设计一套奶牛识别的**产品/服务组合**，交付 **Product Requirements Document + 商业与营销分析**。

## 1. 题目硬约束（不可协商）

| #  | 约束                                          | 对方案的含义                   |
| -- | ------------------------------------------- | ------------------------ |
| 1  | 客户 = 英格兰北部奶农；起步品种 = Holstein Friesian       | 客户段不能泛化到"全英国奶牛场"         |
| 2  | 2026 年 LIS 取代 BCMS，成为登记牛只与申报移动的主系统          | 方案必须有与 LIS 的明确数据接口       |
| 3  | 2027 年起新生犊牛强制 EID，且使用**低频（LF）**&#x6280;术    | 必须兼容 LF 耳标体系，不能自创标签标准    |
| 4  | 纸质牛护照逐步取消，改数字记录                             | 数字化记录链是政策方向              |
| 5  | 失效模式 A：EID 损坏 / 丢失 / 失灵，5 年累计损失高达 **19.8%** | 纯 RFID 方案已被题目判定为不可靠      |
| 6  | 失效模式 B：牛群挤过读取门时**一次读到 2 个 ID**              | 必须有**多读消歧**机制            |
| 7  | 失效模式 C：**完全漏读**                             | 必须有漏读补偿 / 冗余识别路径         |
| 8  | 系统须具备识别稳健性、可靠性、可负担性                         | 三者都要论证，不能只讲技术            |
| 9  | 价格必须由**经济效益**证明（value for money）            | 必须算出"帮农场省/赚多少"，与初装费+年费对比 |
| 10 | 需理解市场需求以得出 USP                              | 先市场后方案，不能先有技术再找需求        |

> 题目的强烈暗示：既然"只靠 RFID 会失败"，方案几乎必然包含**冗余 / 交叉验证的识别路径**。具体选什么模态由本组自行决定。

## 4. 团队规则（建议写进 Cadmus 的 Team Charter）

1. **概念冻结**：Gate 0 之后核心概念（客户段 / 方案方向 / 价格区间）改动需全员同意。
2. **唯一合法的"回头改"入口**是 R8（批判性分析）；一旦改想法，必须同步 Part 1 / 2 / 3。
3. **编辑权边界**：Part 5 只能改格式、引用、错别字；要改别人的论证内容必须找原作者。
4. **数据单一口径**：市场数据、单价、成本模型全篇只允许一套，由 Part 3（数字口径官）维护。
5. **Cadmus 直接输入**：正文不得从 Word / Google Docs 粘贴；画布是上传到小组工作区，不受此限。

## 8. AI 使用边界（Scenario 2 无监考评估）

**允许**：当 critical friend——质疑假设、找推理漏洞、探索替代解释、检查结构与清晰度、挑战你的论证。

**禁止**：让 AI 代做市场分析、实质性写作或最终推荐结论。标注了 AI 使用也不能豁免越界的使用。

**必须声明**：工具名称、版本、发布方、你怎么用的、你的原创贡献是什么。

**材料上传限制**：讲义、评估简报、课件只能上传到学校提供的服务（Microsoft Copilot Chat，学校 M365 账号），且需先取得材料作者许可；书籍/论文等版权材料不应上传到任何工具；真实公司的保密信息与个人数据需先获授权。

## 10. 常见扣分点

1. **画布不可读** = 0 分档（评分原文写了 "not legible"）。拍照别糊，Mural 导出选高清。
2. **R5 与 R11 / R12 明确"无图"**，别再往里塞图。
3. **R10 的图占页数**：最多 2 张，每张抵半页。
4. **R9 的 10 条必须全是 Must have**，出现 Could / Should 等于没按题意做。
5. **R1 要求查政府文件与行业来源**（不是博客），全用厂商页面撑不住那 5 分。
6. **对齐性是全篇主题**：VPC↔客户段、属性↔客户需求、需求↔技术↔价格点、设计↔路线图。任一处断裂会同时拉低 2–3 个章节。
7. **"Formulating the idea: Answer the following question about the idea?"** 里那张 A3 的具体问题清单，模板文档里是空的——需要向老师 / Cadmus 确认，或按 VPC 标准问题回答。
8. **Team Charter 模板本身未在资料中**：Cadmus 里若有"会议记录 / 沟通记录"栏位，以它为准。

## 附录 B：方案设计自查问题

**识别性能**：标签失效时靠什么仍认出这头牛？同时读到 2 个 ID 时如何判定是"两头牛"还是"一头两次"？漏读后如何补录？识别率目标值是多少、凭什么定？

**合规与集成**：牛只身份如何与 LIS 官方登记 ID 绑定？谁在什么时点上报？移动申报是自动触发还是人工确认？数据存哪、断网怎么办？

**农场现实**：泥、粪、水冲洗、低温、氨气、粉尘、电压不稳、无网？谁在用、何时用（挤奶厅 / 通道 / 夜里 / 单人）？安装是否动土建、是否影响牛流线？

**经济**：单头成本多少？对照哪一项损失（追溯罚款 / 奶款扣减 / 人工 / 配种与产奶损失）？按多少头的场算、第几年回本？

**可持续**：材料、能耗、寿命、可维修性、报废处理，哪几条能对上 Dairy Roadmap 的原则？

**可扩展**：从 Holstein Friesian 起步，之后能否扩到其他品种或肉牛？是否影响当前设计选择？
